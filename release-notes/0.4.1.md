## What changed

**It can say what a repository has shipped.** `github_releases` reports
releases newest first *and* tags, because a repository can have one without
the other — this one had eight tags and no releases until the publishing was
wired up, and "no releases" would have read as nothing ever shipping. It
takes `owner/repo`, or a bare repository name when it belongs to one of the
watched users, because a room says "the latest chickenbot release".

Pass `notes=true` and it reads the newest release's own notes, so "what is
in it" is answerable. Without that it has the name and the timestamp and
nothing inside — which it will now say, rather than guess.

**`github_repos` is now `github_user_repos`.** It lists what a *user* owns.
Under the old name it was taking questions about releases — three times out
of three in a selection probe, with the release tool never called. The
rename fixed that where three attempts at rewording did not. See
`UPGRADE_NOTES.md`: a grant naming the old tool is now ignored.

**The live tools remember for five minutes.** `github_commits` and
`github_releases` have no mirror to answer from, so every call was an API
request and asking twice cost twice. The mirror exists so a model can ask as
often as it likes; these now have a short memo for the same reason.

## Fixed

- A tool's reported source was taken from its name before any work happened,
  so a refresh that opened no socket still said "fetched from GitHub" for a
  0ms call. It is now set where the work is, and a transcript can say
  "answered without fetching" or "from a memo, not a call".

## Known rough edges

- A memo hit will not notice a release cut in the last five minutes, and
  `github_refresh` does not clear it.
- "has 0.4.0 shipped yet?", with no repository named, still goes to the
  user listing rather than to releases.
