## What changed

**Releases are built and published by CI now.** Pushing a `vX.Y.Z` tag runs
the checks, builds both source distributions, and creates the GitHub release
from the matching `release-notes/X.Y.Z.md`. `deploy/release.sh patch|minor|major`
does the whole sequence, including writing the version into `pyproject.toml`.

A tag means a release and nothing else does. Deploying still builds from a
checkout and stamps what it finds — `0.4.0+3.g1b19257` three commits past a
tag — so a test build needs no tag, no release, and leaves nothing behind.
Releases before this one have no GitHub release and are not getting one
retroactively; `v0.4.0` is where the record starts.

**`github_commits` says both what landed and where the work is.** Asked
about a repository it now reports the default branch's recent commits *and*
every branch with when it last moved, in one GraphQL request. Either half
alone had already misled a room: a default branch is routinely the stalest
ref there is, and a list of branch tips on a single-branch repo reads as
that repo having one commit — which is what the bot said about this one.

`github_branches` is gone. It returned names without dates and told the
model to get dates from the events feed, which runs hours behind.

**A commit's reason comes back with it.** The recent-commits half of
`github_commits` now carries the first paragraph of each commit body, which
is where this project writes down why a change was made. Asking only for
the subject line threw that away: the bot read one of its own commits, could
not tell whether a tool had been removed deliberately, and asked — when the
answer was in the body it was never sent. Branch tips stay subject-only,
since fourteen branches with bodies is a wall of text about branches nobody
asked after.

**`transcript -1` is the last call**, `-2` the one before it. Reading an id
off a listing first was a step for nothing, and the number you want is
almost always the most recent. Counting back honours `--room` and
`--reason`, so `transcript -1 --room '#lobby'` is the last call in that
room. Counting past the end says how many there are to count through,
rather than claiming nothing is recorded.

## Before you upgrade

Nothing. The previous release needed a database migration; this one does
not. See `UPGRADE_NOTES.md` if you are coming from before `v0.3.4`.

## Fixed

- The `limit` argument to `github_commits` capped branches while the model
  meant commits, so it asked for twenty and got one.
- Commits whose author is not linked to a GitHub account rendered with no
  author at all; they now show the name on the commit.

## Known rough edges

- A dead IRC send or receive pump is reported but does not end the
  connection, so the bot stays in the room and cannot speak. See
  `docs/outstanding.md`.
- `UPGRADE_NOTES.md` and the soul template are not packaged, so an
  installed bot cannot read its own release notes and `chickenbot init`
  cannot find the template it ships with.
